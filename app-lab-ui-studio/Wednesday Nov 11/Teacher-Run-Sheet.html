App Lab launch day

Three blank-screen mini apps. No starter project or asset upload is needed. Print the one-page Student App Lab Passport, open this run sheet, and project or share the three images below. Students keep each app as a separate saved project.

Board message to leave up all period

LOOK → DESIGN → NAME IDs → CONNECT UI BLOCKS → RUN TWO TESTS → SHOW. Every element ID starts with its type: buttonAction, labelMessage, textInputName, screenMain.

Today’s purpose: students can identify an app’s input and output, place and name UI elements, connect a click event to visible feedback, and debug an ID mismatch.

At 8:00, do these four things

  1. Print one copy of Student-App-Lab-Passport.pdf per student.
  2. Open Code.org App Lab; students sign in and choose a new blank app for each mission.
  3. Project Mission 1 build map. The left UI is the finished view; the right adds I/O arrows and IDs.
  4. Tell students the only graded check today is Mission 3. Running and debugging before they say “ready” never uses a grading attempt.

Grade quickly and consistently

Mission 3 is the minor grade. A fully working first ready submission earns 100; second 95; third 90; subtract 5 for each later ready submission. A “ready submission” is an explicit request for your check. Runs, peer tests and help requests do not count. If it fails, tell the student one next action, then return later. Collect the passport as your grade record.

If the room slows down

Keep the same success test. Project the exact IDs and the teacher code file. Have students finish one element or UI block at a time. For Mission 3, the minimum working app is textInputName, buttonMake and labelBadge connected by one click event. A partner may narrate while the builder clicks. Do not add variables, arithmetic or conditionals tomorrow.

Use tomorrow to teach the next three weeks’ workflow

For every later mini app, show its wide build map, then ask students to identify the input and output before coding. Keep the same 3-minute introduction, 5-minute demo, 5-minute guided practice, 14-minute build and 3-minute test rhythm. The student cards and teacher references in the full unit folder follow this pattern; the two major assessments reuse familiar controls without surprise syntax.
