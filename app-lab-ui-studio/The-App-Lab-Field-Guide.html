Build interfaces that respond to people. Start with one button. Finish with apps that combine choices, words, images, sound, and data.

Read in order before class, or jump to the app you are building today.

How to use this guide

Every 30-minute build has one new idea. Read the short explanation, inspect the map, then build in Design Mode. Name every element with a type-first ID, such as buttonCalculate. In Blocks, connect only the UI Controls statements. Your teacher supplies any math, decisions, random values, or drawing code.

On each map, the left screen shows what to make. The second screen repeats it with input and output arrows. The list on the right gives the exact starting properties. Open the SVG at full size when you need to read an ID.

Test before you say an app is ready. A bug is a clue: check the element ID, the event, and the output target one at a time.

Actions and feedback

Week one begins with visible cause and effect. You will make controls respond to taps and typed text, then explore images, screen properties, and menus. The goal is to get comfortable making one small change and proving that it works.

One tap, one response

Week 1, class 1, build 1

A help button in a library or hospital only works if a tap produces a response people can see. Your first app makes that cause and effect visible.

What you will be able to do

Identify a tap as input and changed text as output. Make one button trigger one visible response.

The block idea

onEvent waits for the button tap. setText changes the message label inside that event.

Words in this build

Input
Information or an action sent into an app, such as a tap, typed name, or slider value.
Output
Information an app sends back, such as changed text, a picture, sound, or chart.
User interface
The visible and usable parts that let a person interact with software.

Two actions, one status

Week 1, class 1, build 2

Start and Reset appear on timers, forms, and control panels. Each action needs its own event response, even when both change the same label.

What you will be able to do

Give Start and Reset separate click events. Predict the status after a three-tap sequence.

The block idea

Two onEvent blocks can change the same label in different ways.

Words in this build

Program
A collection of statements that tells a computer what to do.
Program statement
One command in a program, such as setText or setScreen.
Event-driven programming
Code that waits for an action, then runs in response.

Properties change appearance

Week 1, class 2, build 1

Dark mode, high contrast settings, and focus themes are property changes. A good interface keeps its text readable in every state.

What you will be able to do

Change the screen background with setProperty while keeping labels readable.

The block idea

setProperty changes a screen setting while the app runs. Each button can choose a different background.

Words in this build

Property
A setting of an element, such as text, color, position, or value.
User interface
The visible and usable parts that let a person interact with software.
Sequential programming
Statements that run in order, one after another.

Conditional
